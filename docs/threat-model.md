# 威胁模型

本文档列出 Veilink 针对每一类对手**能防什么、不能防什么**。所有结论都可对照代码核对；
任何无法在代码中验证的说法都不会出现在这里。

---

## 0. 前提与信任假设

Veilink 的设计建立在以下假设之上；假设不成立时，下面各节的结论也随之失效：

1. **客户端主机是可信的**。用户自己的机器上没有恶意软件、没有攻击者以同等或更高权限运行。
2. **服务端运营者是可信任的**，或者至少用户接受"VPS 能看到被代理流量的目标与明文（非 TLS）"。
3. **操作系统 CSPRNG 正常**。所有秘密都来自 `getrandom`/`OsRng`；RNG 失败会导致操作失败
   （fail closed），而不是退化。
4. **TLS 实现（rustls + ring）与密码库（RustCrypto、dalek）没有被攻破**。
5. **PSK 是保密的**，且是高熵随机值（`veilink keygen` 产生的 32 字节值）。
6. **客户端与服务器运行的二进制未被篡改**。

Veilink 保护的是**传输路径**，不是端点。端点被攻陷不在保护范围内。

## 1. 被动网络观察者（ISP、上游、本地网络、Wi-Fi 监听者）

**能做什么**

- 记录全部流量：TLS 握手（含 SNI、ALPN、证书）、连接建立/结束时间、字节数、方向、时序。
- 读取 VLP/1 的明文帧头：版本字节、帧类型、`session_id`、`epoch`、`direction`、`sequence`、
  `algorithm`、`key_id`、密文长度。
- 判定"这是 Veilink 流量"（版本字节、ALPN、自签名证书、`veilink.invalid`）。
- 统计帧数、桶化后的帧大小分布、空闲间隔、并发连接数。
- 离线保存所有记录，事后分析。

**Veilink 阻止的**

- 读取任何请求/响应内容：正文、方法、URL、头部、Cookie 都在 AEAD 密文内。
- 读取目标域名与端口（PROXY 路径）：它们在 `OPEN_STREAM` 的加密净荷内；客户端不做本地解析，
  所以本地 resolver 也看不到。
- 区分流 id、区分加密数据与 cover 帧（cover 帧与数据帧使用相同的消息类型与每帧密码学，
  逐帧不可区分）。
- 篡改：任何改动的帧都会因 tag 校验失败而被拒绝并终止会话。

**仍然存在的**

- **全部元数据**：服务端 IP/端口、时序、帧数、桶化长度、协议识别。
- **流量关联与网站指纹**：见第 11 节。
- 若目标走 DIRECT 路径，则观察者与本地 resolver 都能看到该流量的域名与内容（明文 HTTP）。

---

## 2. 主动中间人（MITM：能拦截并改写链路的对手）

**能做什么**

- 拦截 TCP、伪造/替换 TLS 证书、插入或丢弃数据包。
- 尝试把客户端的 TLS 连接终止在自己这里，并另开一条到真实服务端的 TLS 连接（中继）。
- 重放录制的握手消息。
- 阻断连接（DoS）。

**Veilink 阻止的**

- **冒充服务端**：客户端不依赖 PKI，而依赖 PSK 派生的确认 MAC；没有 PSK 无法产生有效 MAC。
  即使出示任意自签名证书也无法通过 VLP/1 握手。
- **中继/透明代理**：`AUTH_CONFIRM` 覆盖了本次 TLS 会话的 exporter
  （`EXPORTER-Veilink-VLP1`）。中继的两条 TLS 会话 exporter 不同，因此服务端生成的 MAC 在客户端
  无法通过验证（`crates/veilink-crypto/src/handshake.rs` 的
  `handshake_fails_when_the_exporter_differs`、`crates/veilink-protocol/src/session.rs` 的
  `a_changed_tls_exporter_fails_the_handshake` 覆盖）。
- **重放旧握手**：录制的握手携带的是当时那条 TLS 会话的 exporter，新会话不会产生该值。
- **降级**：不存在"未认证模式"；TLS 校验以外的任何失败都会立即关闭连接。
- **密钥/密文替换**：76 字节头是 AAD，密文改动、头部改动、跨会话搬运、算法改标签都会被拒绝。

**仍然存在的**

- **DoS / 阻断**：MITM 可以让连接失败，可以丢弃数据。Veilink 不提供抗审查的可用性保证。
- **流量分析**：即使无法解密，仍可做被动观察者能做的一切（第 1 节）。
- **证书特征**：主动对手可以记录自签名证书指纹并据此关联同一服务端。
- 如果 PSK 已经泄露给该 MITM，则它能完整冒充服务端（第 8 节）。

## 3. 恶意或被攻陷的客户端（持有 PSK 的攻击者，例如被泄露的客户端配置）

这是 Veilink 明确要限制的对手：**认证只证明"持有 PSK"，不证明"被授权去哪"**。

**能做什么**

- 通过认证，使用服务端作为出口。
- 对**公网**的允许端口发起任意连接（可能被当作开放代理滥用）。
- 请求任意主机名（服务端会解析它）。
- 大量并发连接/流以消耗服务端资源。

**Veilink 阻止的**

- **访问 VPS 自身网络**：`EgressPolicy` 默认拒绝 loopback、RFC 1918 私网、link-local
  （含云元数据 `169.254.169.254`）、CGNAT、benchmarking、documentation 网段、组播与保留地址。
  无论 `allow_private_targets` 如何，`0.0.0.0/8`、`224.0.0.0/4`、`240.0.0.0/4`、
  `255.255.255.255/32`、`192.0.0.0/24` **始终**被拒绝。
- **DNS rebinding / TOCTOU**：策略作用于**解析后的地址**，并且连接到**已校验的那个地址**
  （绝不把域名交给 socket API、绝不重新解析）。若某域名解析出公私混合地址，**整体拒绝**
  （`filter_addresses`），而不是静默过滤——那正是 rebinding 的强信号。
- **端口限制**：`allowed_ports` 非空时只允许列表中的端口（空表示全部）；端口 0 一律拒绝。
  端口检查在解析之前短路执行。
- **无限资源占用**：并发连接上限、每会话流数上限、单帧最大长度、头部大小上限、空闲超时、
  按源 IP 的连接速率限制。
- **读取其他客户端的数据**：会话之间密钥独立（`session_id` 派生自各自的 transcript 与
  exporter），跨会话帧被拒绝。

**仍然存在的**

- **没有按客户端的身份、配额或吊销**。所有 PSK 持有者完全等价：无法单独封禁一个客户端，
  除非轮换 PSK（会同时影响所有客户端）。也没用流量配额、总带宽限制或按客户端速率限制。
- **开放代理风险**：只要目标在公网且端口被允许，攻击者就能用它发起连接。限制手段只有
  `allowed_ports` 与网络层的出站防火墙。
- **服务端可被用作探测工具**：攻击者可以让服务端去连接公网主机的允许端口（端口扫描的间接形式）。
- 服务端无法区分"合法用户的客户端"与"偷到配置的攻击者"。

---

## 4. 未认证连接（无 PSK 的探测者）

**能做什么**

- 完成 TLS 握手（因为客户端侧的证书校验不做 PKI 验证，服务端只是出示自签名证书）。
- 反复发起 TLS 握手以消耗连接槽与 CPU。
- 观察服务端是否响应、TLS 证书内容、ALPN。

**Veilink 阻止的**

- **读取或写入任何代理数据**：服务端在读取第一个代理请求之前必须先完成 VLP/1 握手
  （`relay_streams` 只在 `start_session` 成功后运行）。
- **握手预言机**：失败只记录 debug 日志，错误路径不区分"PSK 接近正确"等信息；`ServerError::Handshake`
  不携带原因。
- **重放**：无 PSK 无法产生有效 MAC；有录制的 MAC 也因 exporter 不同而失败。
- **资源耗尽的部分缓解**：按源 IP 的速率限制（`accept_rate_per_second`，默认 64/秒）与并发连接
  上限；失败的握手计入 `auth_failures`。

**仍然存在的**

- **TLS 握手本身可被消耗**：速率限制是每源 IP 每秒的计数窗口，分布式来源仍可造成压力；
  没有全局 CPU 预算、没有工作量证明、没有连接前挑战。
- **服务端存在性可被探测**：未认证对手可以确认"这里有一个 TLS 服务在监听"。
- **指纹**：自签名证书与行为特征可被记录。

---

## 5. 被攻陷的 VPS（服务端运营者作恶，或 VPS 被入侵）

这是 Veilink **无法在密码学上防范**的对手，因为它就是出口。

**能做什么**

- 看到所有 PROXY 流量的**目标域名与端口**（它执行远端解析）。
- 对非 TLS 的代理流量（明文 HTTP），看到并修改**全部明文内容**（Veilink 不终止内层 TLS，
  但明文 HTTP 本来就没有内层 TLS）。
- 对 HTTPS：只能看到"连接到哪个域名/IP/端口"，看不到内容（内层 TLS 由客户端与目标端到端协商）。
- 记录域名、时间、字节数；丢弃、延迟、篡改响应；拒绝服务。
- 打开 `log_domains` 后把域名写入日志。

**Veilink 阻止的**

- **读取已录制帧**：即使 VPS 保留全部密文，帧密钥来自已擦除的一次性交换，无法事后重算。
- **解密后再录制的历史流量**：同上。
- **看到 DIRECT 流量**：客户端直连的流量不经过 VPS。
- **看到内层 TLS 明文**：CONNECT 隧道是裸字节管道，代理不终止 TLS。

**仍然存在的**

- **元数据完全暴露给 VPS**：目标域名、端口、时间、规模。这是使用自建代理的固有代价。
- **明文 HTTP 的内容暴露**。
- **主动篡改**：VPS 可以修改明文 HTTP 响应、注入内容、返回错误。Veilink 没有签名/审计机制能让
  客户端检测服务端的篡改（除内层 TLS 自身提供的保护外）。
- **可用性**：VPS 可以随时拒绝服务。
- 如果 VPS 被入侵者控制且该入侵者能**实时**读取进程内存，前向保密的前提被破坏
  （见 `docs/cryptography.md` 第 5.2 节）。

---

## 6. 被攻陷的客户端主机（用户自己的机器被入侵）

**能做什么**

- 读取客户端进程的内存：PSK、当前会话的一次性私钥、控制链状态、明文 HTTP 内容。
- 读取 `state_dir` 下的文件；读取配置文件（含 PSK）。
- 修改配置文件、替换二进制、直接绕过代理访问网络。
- 观察用户的所有操作（键盘记录、屏幕截图等）。

**Veilink 阻止的**

- 几乎没有。Veilink 是一个用户态代理，无法对抗同机上的更高权限攻击者。
- 仅有的缓解是**减少暴露面**：秘密用 `Zeroizing` 包裹、`Debug`/`Display` 全部脱敏、不写日志、
  `identity.key` 与 `tls_key.pem` 权限 0600、打开 tag 校验失败时先擦除缓冲区。

**仍然存在的**

- 本机恶意软件可以看到一切。**端点安全不在 Veilink 的防护范围内。**
- 配置里的 PSK 一旦被读走，攻击者可以冒充客户端或服务端（第 8 节）。
- 恶意软件可以完全不使用代理，直接把流量发出去（Veilink 无法阻止）。

---

## 7. 已录制的历史流量（"先记录，后解密"）

**能做什么**

- 长期保存全部密文、帧头与时序。
- 事后获得 PSK、服务端身份私钥、或服务端主机访问权。

**Veilink 阻止的**

- **事后用 PSK 解密**：应用帧密钥来自一次性 X25519 交换；接收方私钥在使用后即被移除并擦除。
  因此后来的 PSK 泄露**不能**解密已录制的应用帧。
- **事后用长期身份私钥解密**：该私钥不参与任何帧密钥派生。
- **事后用控制链解密**：控制链根虽由 PSK 派生，但还需要**该会话的 TLS exporter**（源自 TLS 主密钥，
  不可从录制流量导出）。控制帧只含密钥池元数据，不含用户数据。

**仍然存在的**

- **元数据永久留存**：帧数、时序、桶化长度、连接关系永不失效，可长期用于关联与指纹分析。
- **录制时的内存捕获**：如果攻击者在录制期间能读取服务端或客户端内存，前向保密不成立。
- **尚未被消费的一次性私钥**：会话仍存活时的帧密钥材料若被实时读取，则该帧可被解密。
- **控制帧**：在同时掌握 PSK 与该会话 exporter 的情况下可被解密（只含 `KEY_OFFER`/`KEY_ACK`/
  `PING`/`PONG`/`GOAWAY` 等元数据）。

---

## 8. PSK 泄露

**能做什么**

- **冒充服务端**：对**未来**会话实施 MITM（客户端只用 PSK 认证服务端）。
- **冒充客户端**：连接真实服务端并使用其出口（受 egress 策略限制）。
- 与某会话的 TLS exporter 结合时，解密该会话的控制帧。
- 派生控制链根（需要 exporter）与握手密钥。

**Veilink 阻止的**

- **解密已录制的应用帧**：帧密钥与 PSK 无关。
- **绕过 egress 策略**：策略由服务端执行，与认证无关。
- **重放旧会话**：exporter 逐会话唯一，录制握手无法在新会话通过。
- **推导长期身份私钥**：两者独立。

**仍然存在的**

- 泄露窗口内服务端可被冒充；这是任何 PSK 方案的固有性质。
- **没有前向保密的认证**：PSK 是长期共享秘密，没有每客户端密钥、没有证书、没有可吊销凭证。
- 轮换是唯一处置手段，且必须**客户端与服务端同时**更换（当前没有平滑轮换机制）。
- 没有密钥版本/`kid` 概念，因此无法在不清断服务的情况下做双密钥过渡。

---

## 9. 服务端长期身份私钥泄露（`identity.key`）

**能做什么**

- 伪造与真实服务端"身份相同"的 TLS 证书与 `SERVER_HELLO`。
- 如果同时拿到 PSK，则完整冒充服务端。
- 使任何**已启用**的身份指纹 pinning 失效（检测被绕过的前提是攻击者不持有身份私钥）。

**Veilink 阻止的**

- **解密任何帧**：该私钥不参与帧密钥派生，也不派生任何会话密钥。
- **在只有身份私钥、没有 PSK 时冒充服务端**：VLP/1 握手仍会因 MAC 失败而拒绝。
- **解密已录制流量**。

**仍然存在的**

- 服务端"同一实例"的可识别性被破坏。**若客户端设置了 `server_identity_pin`**，替换会被检测到并
  导致连接失败（可见故障而非静默接受）；**若未设置**（默认），客户端不会察觉，只能靠操作者人工
  核对日志中的指纹。
- 注意：pinning 只检测"身份被换"，不能阻止持有 **PSK** 的攻击者（第 8 节）；两者结合才能完整
  冒充服务端。

---

## 10. DNS 泄露

**能做什么（取决于用户环境）**

- 本地网络/ISP 的 resolver 观察所有**未被代理**的 DNS 查询。
- 浏览器/操作系统可能**预解析**（prefetch/preconnect）或使用 **DoH/DoT**，这些查询完全绕过
  HTTP 代理。
- 应用如果忽略代理设置或使用非 HTTP 协议，流量与 DNS 都不会经过 Veilink。
- 客户端解析**服务端域名**时必须使用本地 resolver（若 `server` 写的是域名）。
- 服务端的 resolver（或系统 resolver）能看到它代理解析的所有域名，VPS 运营者也能看到。

**Veilink 阻止的**

- **PROXY 路径的域名对本地 resolver 不可见**：客户端把规范化域名原样放入加密帧，服务端远程解析。
- **IP/CIDR 规则不会诱发本地解析**：`IP`/`CIDR` 规则只匹配 IPv4 字面量，因此不需要为了评估规则而
  解析域名（这是刻意的设计，见 `veilink-rules` 模块文档）。
- 白名单命中但隧道不可用时**直接失败**，不会回退到本地解析+直连。

**仍然存在的**

- 上述预解析/DoH/direct-connection 路径导致的域名泄露**完全不经过 Veilink**，Veilink 无法阻止。
- DIRECT 路径的域名与内容对本机 resolver、ISP 与网络观察者可见（这是"直连"的定义）。
- 服务端侧域名可见（对 VPS 运营者）。
- 客户端的 `server` 域名查询可见（若写成域名而非 IP）。
- 如果 DoH/DoT 与代理同时使用，DNS 路径与流量路径分离，可能出现"域名已通过 DoH 解析、随后连接
  走了代理"或"连接直连"的不一致，需要用户自行核对（README 中有显著提示）。

## 11. 流量关联与网站指纹（Website fingerprinting）

**能做什么**

- 把"用户接入链路"的流量与"到 VPS 的链路"的流量做时间/体积关联，确认二者相关。
- 用包长分布、方向比例、时序、突发结构训练分类器，推断访问的网站类别甚至具体站点。
- 使用帧数、桶分布、空闲模式区分"下载大文件""加载网页""流媒体"等行为。
- 识别协议（因此知道"正在使用 Veilink"）。

**Veilink 阻止的**

- **长度细粒度**：固定桶填充把明文长度粗化到桶，隐藏真实消息长度（如 3 字节与 500 字节的密文
  长度相同）。
- **内容与目标**：分类器无法直接读取域名或 URL。

**仍然存在的**

- **时序被削弱但未被消除**：批量合并（最多 16 帧 / 64 KiB 一次写出）与带抖动的节奏整形
  （仅在本批之后还有排队消息时生效，单帧最多推迟 50 ms，`oldest_wait` 超限时立即发送，见
  `docs/privacy.md` 第 3.2 节）会削弱"每帧一次写出"的细粒度时间特征，但帧的时间分布仍然与
  应用活动相关，且本仓库**没有任何检测率评估**。
- **桶分布仍可区分**：桶本身携带信息（小请求 vs 大响应）。
- **帧数与方向比例可见**：一次页面加载的请求/响应帧数与比例是强特征。
- **没有任何抗指纹评估**：本仓库没有检测率测量、没有对抗性数据、没有真实网络评估。
  因此**不得**声称任何"检测率"或"不可指纹化"。
- **cover traffic 只覆盖空闲期且会停止**：会话空闲 750 ms 后开始，每 1.5 秒一个突发、每突发最多
  3 帧、最多 40 个突发（约 60 秒）后停止，并受 4 KiB/s 与每会话 256 MiB 的预算约束。因此：
  长时间静默之后仍会完全静默；活跃期的帧仍然全部对应真实活动；cover 突发不产生响应，
  双向观察者可据此区分。
- **没有恒定速率**、没有恒定速率填充、没有批处理之外的延迟随机化、没有混合网络（mixnet）设计。
  仓库中**没有任何**抗指纹/抗分类评估。

## 12. 其它对手与场景

| 对手/场景 | Veilink 的处理 |
|-----------|---------------|
| 端口扫描者 | 只有 TLS 端口可见；未认证流量被速率限制；无法通过代理探测内网（egress 策略） |
| 服务端被用作 DDoS 放大器 | 认证之后才能开流；没有 UDP；没有放大语义；但仍是可滥用的出口（第 3 节） |
| 重放帧 | 应用帧：序号 + 一次性密钥双重拒绝；控制帧：棘轮拒绝 |
| 帧篡改/改标签 | 头部为 AAD；算法/方向/会话/epoch/序号/key id/nonce/临时公钥任一改动都会失败 |
| 跨会话混淆 | `session_id` 派生自各自 transcript+exporter；跨会话帧被拒绝 |
| 资源耗尽（慢读） | 双向信用流控 + 有界出站队列，慢读者只产生反压 |
| 超大头部/超长字段 | 头部上限 64 KiB、target 8 KiB、握手消息 8 KiB、帧长度上限 69648、消息字段上限明确 |
| 崩溃/DoS 导致密钥残留 | `Zeroizing` + 校验失败先擦除；但 swap/内存快照风险仍在（第 6 节、cryptography.md 5.2） |
| 量子计算机 | **无防护**：X25519 不抗量子；没有 PQ 混合密钥协商 |

## 13. 范围总结

**在防护范围内**

- 传输内容的机密性与完整性（对被动观察者与主动 MITM）。
- 服务端认证（PSK + TLS channel binding），无法降级、无法中继、无法重放握手。
- 每帧前向保密（在私钥被真正擦除这一前提成立时）。
- 客户端对目标域名的本地解析隐藏（PROXY 路径）。
- 已认证客户端的 egress 约束（特殊用途地址、可选端口列表、DNS rebinding、资源上限）。
- 长度粗化（固定桶填充，始终生效）。

**明确不在防护范围内**

- 端点安全（客户端主机或 VPS 被攻陷）。
- 元数据隐私（IP、时序、帧数、桶分布、协议存在性）。
- 抗流量关联、抗网站指纹、抗流量分类（填充只粗化长度；cover 仅覆盖空闲期；节奏整形有界且
  未经评估；仓库中没有任何检测率评估）。
- 匿名性（无洋葱路由/混合网络）。
- 抗审查可用性（无域前置、无流量伪装保证、无抗封锁设计）。
- 抗量子攻击。
- 对 VPS 篡改明文 HTTP 的检测。
- 按客户端的身份、配额与吊销。
- 用户侧 DNS 泄露（预解析、DoH、绕过代理的流量）。
